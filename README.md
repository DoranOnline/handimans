# HANDIMANS

מרקטפלייס לבעלי מקצוע בבית, בנוי סביב **אזור שירות ורדיוס** — לא סביב רשימה.
ארבעה צדדים מלאים: לקוח, בעל מקצוע, קבלן (עסק עם צוות), מנהל.

**דמו חי (סטטי):** https://handimans-demo.netlify.app
**קוד:** https://github.com/DoranOnline/handimans

## האפליקציה האמיתית — `app/`

לא פרוטוטייפ: שרת Node אמיתי, מסד SQLite, אימות, יתרות וכסף, ויומן עם בקרת התנגשויות.
אפס תלויות חיצוניות (רק `node:sqlite` ו-`node:http`), לכן אין `npm install`.

```bash
cd app
npm start          # http://127.0.0.1:4173
npm test           # 32 בדיקות קצה-לקצה מול השרת הרץ
npm run seed       # איפוס ובנייה מחדש של הדאטה
```

חשבונות דמו (סיסמה `demo1234`): `customer@demo.co.il`, `pro@demo.co.il`, `biz@demo.co.il`, `admin@demo.co.il`.

מה אמיתי: הרשמה והתחברות עם scrypt וסשן ב-cookie, חיפוש לפירדיוס וחישוב haversine, בקשות והצעות, חיוב 100 ₪ לפנייה בטרנזקציה עם רשומת תנועה, יתרה וטעינה, יומן עסק עם קיבולת איש צוות וחסימת כפילות, עמוד ציבורי עם קביעת תור, וצד מנהל עם הכנסות והגדרות.
מה לא: סליקה אמיתית (טעינה מדומה), התראות push, צ׳אט, ואין עדיין אחסון ענן — רץ מקומית.

## הפרוטוטייפ

### אונליין (להראות ללקוח)
https://handimans-demo.netlify.app — עמוד כניסה עם ארבעה כרטיסים, כל אחד נכנס לצד שלו.

### מקומית
```bash
cd prototype
python -m http.server 5173
# http://localhost:5173
```

עמוד אחד, ארבע תצוגות. מחליפים צד בכפתור למעלה: **לקוח / בעל מקצוע / קבלן / מנהל**.

### צד לקוח
- מפה עם 16 בעלי מקצוע, סיכות לפי קטגוריה, נקודת עבודה draggable.
- רדיוס 1–30 ק״מ עם עיגול חי, סינון ומיון (התאמה / מרחק / דירוג / מחיר).
- ניקוד התאמה משוקלל: מרחק, דירוג, זמינות, אמינות, זמן תגובה.
- בקשת שירות עם תיאור, דחיפות, תקציב ותמונות.
- השוואת הצעות, אישור, יצירת עבודה, צ׳אט עם מענה, דירוג אחרי סיום.

### צד בעל מקצוע
- דשבורד: פניות, המרה, הכנסה, דירוג, גרפים ומשפך.
- פניות מסוננות לפי מקצוע ורדיוס, שליחת הצעה עם חיוב 100 ₪ לפנייה.
- ארנק בשקלים, טעינת יתרה ויומן תנועות.
- יומן שבועי, מעבר סטטוס עבודה, פרופיל עם מפת אזור שירות, דירוגים.

### צד קבלן (עסק עם צוות)
- סקירה: תורים היום, ניצולת צוות, הכנסה מתוכננת, לקוחות חוזרים, ביקוש לפי שירות.
- יומן שבועי 7×10 שעות עם משבצות לחיצות, קיבולת במקביל וצביעה לפי איש צוות.
- תור המתנה עם דחיפות ושיבוץ בלחיצה, צוות עם עומס יומי והשבתה.
- עמוד ציבורי: שירותים ומחירים, שעות, אזור שירות, תצוגת לקוח, המרה ומקורות תנועה.
- פניות באזור ב-100 ₪ לפנייה, הגדרות עסק: שעות, משך תור, קיבולת, פיקדון, אישור אוטומטי.

### צד מנהל
- סקירה תפעולית: GMV, שיעור מילוי, היצע, מחלוקות.
- תור אימות עם אישור/דחייה וחסימת קטגוריות מסוכנות.
- ניהול מחלוקות עם הכרעה וזיכוי.
- משתמשים, השעיה, קטגוריות ותמחור, התאמת יתרות, יומן פעילות, הגדרות.

הדאטה בדויה, לצורכי הדגמה בלבד. כל הפעולות משנות state בזיכרון ומתאפסות ברענון.

## פריסה

הדמו סטטי לחלוטין — אין build ואין שרת. כל שינוי בקוד מתפרסם כך:

```bash
rm -rf dist && mkdir -p dist
cp index.html dist/ && cp -r prototype dist/prototype && printf '' > dist/.nojekyll
netlify deploy --prod --dir=dist
```

האתר יושב על Netlify (חינם) בפרויקט `handimans-demo`. GitHub Pages כבוי בכוונה:
החשבון מקושר לדומיין `burnbright.click` ולכן `github.io` מפנה לשם ומחזיר 404.

## הצעד הבא

1. לקרוא את האפיון ולסמן מה נכנס ל-MVP ומה נדחה.
2. להחליט על 3 שכונות להשקה ועל 3 קטגוריות פתיחה.
3. להרים את השלד: `pnpm create next-app` + `supabase init` + `db/schema.sql`.
4. לבנות בקשה אחת מקצה לקצה לפני שמוסיפים עוד מסכים.
